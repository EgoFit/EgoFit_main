# Project Architecture

## Repository layout

- `manage.py` is the Django command entry point; `sport_shop/` contains project settings, root URL routing, ASGI/WSGI entry points, Celery setup, middleware, storage, and startup support.
- `account/` owns authentication, profiles, workouts, documents, and the staff admin portal. Feature URL/view packages live under `auth/`, `profile/`, `workouts/`, `documents/`, and `admin_portal/`; shared domain, service, selector, repository, task, template, and migration code remains in the app.
- `home/` owns public pages and course, article, search, and video features. Its feature logic is split across views, services, selectors, repositories, and tasks, with templates under `home/templates/`.
- `cart/` owns the cart, orders, discounts, and payment flow. It contains service, selector, repository, and payment-provider modules, with templates under `cart/templates/`.
- `api/` exposes the client API. Versioned endpoint modules live in `api/v1/`; shared API authentication, middleware, response, and request utilities remain in `api/`.
- `context_processors/` supplies shared template context. Shared templates live in `templates/`; application-specific templates stay with their Django app.
- `assets/` contains source CSS, JavaScript, images, and fonts. Frontend Playwright specs live in `tests/frontend/`; Django tests are colocated with their apps. `staticfiles/` is generated by `collectstatic` and is not source code.

## Feature boundaries

The account application keeps its public URLs under the /accounts/ path while organizing request handlers by feature:

- `account/auth/` contains authentication URLs and compatibility exports for the legacy authentication handlers.
- `account/profile/` contains profile URLs and profile views.
- `account/workouts/` contains workout-program URLs and views.
- `account/documents/` contains document and workout-program payment URLs and compatibility exports.
- `account/admin_portal/` contains staff portal and gym-library URLs and views.

The existing `account/views.py`, `account/profile_views.py`, `account/workout_views.py`, `account/admin_portal_views.py`, and `account/admin_portal_gym_views.py` import paths remain available for third-party or older internal imports.

## API boundaries

The root router mounts `/api/v1/` through `api/urls.py`, which delegates to `api/v1/urls.py`. Versioned endpoint groups are:

- `api/v1/auth/` contains authentication endpoint exports.
- `api/v1/profile/` contains authenticated user and profile endpoint exports.
- `api/v1/content/` contains course, article, search, comment, and video endpoint exports.
- `api/v1/commerce/` contains cart, order, and payment endpoint exports.
- `api/v1/library/` contains read-only exercise, muscle, corrective-exercise, and lookup endpoints.

`api/views.py` re-exports views from the versioned modules for compatibility. New endpoint work should be placed in the matching `api/v1/<feature>/` module rather than adding code to that facade.

## Root URL routing

`sport_shop/urls.py` mounts the public site at `/`, the HTML account and admin portal at `/accounts/`, commerce at `/cart/`, and the client API at `/api/v1/`. Django's built-in admin is mounted at `/Mpannel/`.

## URL compatibility

The historical `register` namespace remains valid. The `account` namespace is also available as a compatibility alias; both resolve to the same `/accounts/` URLs. Public paths are unchanged.

## Template boundaries

The shared header is split into `templates/includes/header_desktop.html` and `templates/includes/header_mobile.html`. The gym exercise form keeps its large catalog data in the main template while rendering the editable form fields through `account/templates/admin_portal/gym/partials/exercise_fields.html`.

## Validation

Use the following checks before merging structural changes:

    python manage.py check
    python manage.py makemigrations --check --dry-run
    python manage.py test account.tests_url_architecture api.tests_url_architecture
    python manage.py test account.test_security_payments api.tests_auth api.tests_ownership api.tests_payments
